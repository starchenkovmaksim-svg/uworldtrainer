# Публикация и общий прогресс

Сайт опубликован: https://starchenkovmaksim-svg.github.io/uworldtrainer/
Проект Supabase подключён через публичный ключ в `config.js`; таблица и политики установлены.
Ниже — инструкция для повторного развёртывания. При существующей базе повторно выполнять SQL не нужно.

## 1. Supabase

1. Создайте проект на https://supabase.com/dashboard .
2. В SQL Editor выполните содержимое `supabase.sql` один раз.
3. В настройках проекта скопируйте Project URL и Publishable key (допустим также legacy anon key) в `config.js`.
   **Secret key, service_role и пароль базы сюда не вставлять.**
4. В Authentication → URL Configuration укажите адрес сайта GitHub Pages как Site URL и добавьте его в Redirect URLs (с завершающим `/`).
5. В Authentication включите Email. Вход использует стандартную ссылку из письма.
   У встроенной почтовой службы Supabase есть ограничения: для обычных пользователей настройте собственный SMTP; без него проверяйте вход только для разрешённых адресов команды проекта.

## 2. GitHub Pages

Репозиторий пользователя: https://github.com/starchenkovmaksim-svg/uworldtrainer .
Загрузите содержимое этой папки в его корень, включая `assets`, `data.js`, `.nojekyll`, `config.js`, `progress.js` и `cloud.js`.
Изображений около 3000 (вся папка около 205 МБ), поэтому для загрузки удобнее GitHub Desktop или Git, а не веб-форма.

В Settings → Pages выберите Deploy from a branch → main → / (root).
Ожидаемый адрес после включения GitHub Pages:
`https://starchenkovmaksim-svg.github.io/uworldtrainer/`
Сайт опубликован по этому адресу.

GitHub Pages раздаёт файлы сайта публично. Вход защищает записи прогресса в базе, а не HTML и изображения заданий.

## 3. Проверка после настройки

1. Откройте сайт, введите почту и перейдите по ссылке из письма на том же устройстве.
2. Решите вопрос и дождитесь «Сохранено в облаке».
3. Войдите с той же почтой на втором устройстве — ответ должен появиться.
4. Проверьте отметку вопроса, самопроверку и сброс блока на обоих устройствах.
5. При потере сети очередь хранится в браузере аккаунта и отправляется после восстановления связи.

Обновление происходит после изменения, при возвращении во вкладку и каждые 15 секунд в открытой вкладке.
При одновременном изменении одного вопроса побеждает последняя доставленная серверу версия этого вопроса. Изменения разных вопросов объединяются атомарно.
При сбросе отправляются пустые ответы блока. Не сбрасывайте блок одновременно с решением на другом устройстве.
Без входа прогресс остаётся локальным; при входе используется прогресс аккаунта. Старые ответы не переносятся.
Локальная папка с изображениями работает без сети; опубликованный сайт не гарантирует загрузку ещё не открытых изображений без интернета.

Схема использует RLS: пользователь может читать и менять только свою строку. Проверка изоляции двух реальных аккаунтов требуется после подключения проекта.
